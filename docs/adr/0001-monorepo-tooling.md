# ADR-0001: Monorepo with pnpm and uv workspaces

- Status: Accepted (Phase 0)
- Date: 2026-11-07

## Context
The PRD fixes the layout: `apps/web`, `apps/api`, `apps/worker`, `packages/shared`, `infra/`, `docs/`. We need one checkout with Python and TypeScript sharing contracts, and reproducible installs.

## Decision
- **JavaScript:** pnpm workspaces (`apps/web`, `packages/*`), pnpm 10.34.9 pinned in `packageManager`. Exact versions are pinned in `package.json`, and `pnpm-lock.yaml` is committed.
- **Python:** a uv workspace (`apps/api`, `apps/worker`) with one `uv.lock`. The worker depends on the API package (`momentsales-api`), so models and services exist once.
- **Shared contracts:** the API's OpenAPI spec (`docs/openapi.json`) and the role matrix (`packages/shared/src/generated/permissions.json`) are generated by `python -m momentsales.tools.export_contracts`. `openapi-typescript` turns the spec into TS types. CI fails if any of them is stale.
- The root `pyproject.toml` holds ruff, mypy (strict), pytest and coverage settings.

## Consequences
- One `uv sync` and one `pnpm install` set up everything.
- `pnpm` is run via `npx pnpm@10.34.9` locally, because the bundled corepack (Node 22.11) fails signature verification. CI uses `pnpm/action-setup`.
